# Backend foundation (M1 and M2)

The backend is a single ASP.NET Core Web API targeting .NET 10, with an xUnit
integration test project. Future modules will live within the API project.

From Git Bash:

```bash
cd '/k/School Management/backend'
dotnet restore SchoolAdmission.sln
dotnet build SchoolAdmission.sln --no-restore
dotnet test SchoolAdmission.sln --no-build

cd SchoolAdmission.Api
ASPNETCORE_URLS=http://localhost:8080 dotnet run --no-launch-profile
```

In a second terminal:

```bash
curl -i http://localhost:8080/health
```

The only endpoint is controller-based `GET /health`, returning HTTP 200 with
`{"status":"healthy"}`.

Configuration uses standard ASP.NET Core providers, including environment variables:

- `ASPNETCORE_URLS` sets the listening address; no port is hard-coded.
- `HOLD_DURATION_SECONDS` defaults to `600` when absent. Startup fails if the value
  cannot be parsed as a positive 32-bit integer. This only prepares configuration;
  no seat hold behavior is implemented.
- `ConnectionStrings__DefaultConnection` configures `AppDbContext`. Its committed
  value remains empty. A missing value only fails when a context is requested;
  `/health` stays a liveness check and does not test database readiness.
  Keep real credentials out of source control.

## M2 local PostgreSQL and migrations

Requires .NET 10 and Docker Desktop running Linux containers with Compose.
`compose.db.yml` runs only local PostgreSQL, not the final application stack.
The credentials below are deliberately non-production examples. Dev and test use
separate servers, database names, loopback ports, and named volumes.

From Git Bash in `backend/`:

```bash
docker compose -f compose.db.yml up -d --wait
dotnet tool restore
dotnet restore SchoolAdmission.sln
dotnet build SchoolAdmission.sln --no-restore

export ConnectionStrings__DefaultConnection='Host=127.0.0.1;Port=5432;Database=school_admission;Username=school_admission_dev;Password=local_m2_only'
dotnet ef database update --project SchoolAdmission.Api --startup-project SchoolAdmission.Api

# Offline migration checks (no PostgreSQL connection needed):
dotnet ef migrations has-pending-model-changes --project SchoolAdmission.Api --startup-project SchoolAdmission.Api
dotnet ef migrations script --project SchoolAdmission.Api --startup-project SchoolAdmission.Api
```

Initial migration: `20261110133159_InitialDatabase`. Migration SQL is generated by
EF Core 10.0.14 with Npgsql EF provider 10.0.3. All Microsoft EF packages and the
local `dotnet-ef` tool are pinned to 10.0.14. The API never applies migrations at
startup. UUIDs are generated in .NET; callers must supply UTC timestamps.

## Real PostgreSQL tests

```bash
# Safe without PostgreSQL: health runs; unconfigured database tests report SKIP.
dotnet test SchoolAdmission.sln --no-build

# Explicitly enable database tests against the separate local test server:
export SCHOOL_ADMISSION_TEST_CONNECTION='Host=127.0.0.1;Port=5433;Database=school_admission_m2_tests;Username=school_admission_test;Password=local_m2_test_only;Timeout=5'
dotnet test SchoolAdmission.sln --no-build --filter 'Category=PostgreSQL' --logger 'console;verbosity=normal'

# Run health and database tests together once configured:
dotnet test SchoolAdmission.sln --no-build
```

Tests only accept the exact database name `school_admission_m2_tests`. They apply
the checked-in migration to that dedicated database and run each test's writes
inside a transaction that rolls back on disposal. No `EnsureDeleted`, database
drop, SQLite, or EF InMemory provider is used. Use this database exclusively for
tests: its schema persists, but test records do not. If a connection is supplied
and PostgreSQL is unreachable, tests fail instead of silently skipping.

The PostgreSQL suite checks valid persistence, all active-status duplicate pairs,
expired/cancelled history, malformed birth-registration numbers, seat counts,
status validation, case-insensitive class names, foreign keys, column types,
nullability, and index definitions. Missing database configuration produces
explicit skips, which do not constitute database verification.

Stop local servers without deleting data:

```bash
docker compose -f compose.db.yml down
```

The schema and exact quoted PostgreSQL identifiers are documented in
[`docs/DATABASE_DESIGN.md`](../docs/DATABASE_DESIGN.md). Verification status and
remaining local checks are recorded in
[`docs/IMPLEMENTATION_PLAN.md`](../docs/IMPLEMENTATION_PLAN.md).
